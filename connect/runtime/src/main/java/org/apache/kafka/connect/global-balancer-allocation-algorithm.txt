Two constraints here we need to work with.
1st - each consumer will have a cNmin and cNmax task allocation per worker
2nd - each worker node will have cNmin and cNmax tasks allocation overall


What to do for Revocations
Sort workers by task count with most loaded workers in decending order, include all workers
Start revoking all the tasks that violate per consumer allocation per worker constraint i.e. 
For each worker
 - Remove all tasks for each consumer that violates consumer task count > cNmax for that consumer on that worker, Append these removed tasks to revoke task list
 - Once the above revocation is done, we need to find if there are additional consumers that will need to be revoked to meet the balance since there could be a situation where we can end up with too many workers having cNmax tasks for a consumer and rest of the workers end up with less than cNmin tasks for that consumer. To find this, we need to:
    - First find the total number of workers that has cN==cNmax (tasks_consumerN_max), basically count the (sum of all tasks for that consumer)==cNmax (tasks_consumerN_max) after removing > cNmax tasks count on each worker 
    - Then calculate, the expected woker count for the entire cluster with cNmax value as, expected_tasks_cNmax_count = (total c1 tasks) - (total_workers * cNmin)
    - Remove tasks if (tasks_consumerN_max > expected_tasks_cNmax_count) remove_additional_tasks = tasks_consumerN_max - expected_tasks_cNmax_count. Append these removed tasks to revoke task list
    - At this point we should have a balanced revocation list that meets both per consumer and per worker task constraints


What to do for Assignment
Sort workers by task count least loaded worker including worker with 0 allocation
Sort consumers by highest cNmin number

For each worker in sorterd worker list
  - For each consumer in sorted consumer list
    - check if cNmin > running task count, if it is true, then allocate tasks for that consumer on that worker until it reaches cNmin for that consumer on that worker
  - At this point there should be no consumers with more than 2 unallocated tasks, we can now do a round robin allocation of remaining unallocated tasks to each worker until we reach tasks_per_worker_max for that worker or we run out of unallocated tasks
